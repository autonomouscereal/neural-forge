## 0. The one decision everything else hangs on: what "the skeleton" is

Cyril's standing rule makes Chimera Omni the target platform (P9, 2026-08-04) and makes it dense (P35, P47, DENSE RULE 2026-08-28). The Chimera repo's trunk today is K3-shaped: KDA + gated-MLA + Block-AttnRes + SiTU + dense FFN + encoder-free native media (READ 3). The only large dense donor that exists in HF weights is Qwen3.8-27B (download launched 2026-09-01, pid 2227173, 18 shards, 55.6 GB bf16; memory 2026-09-01), and its trunk is *also* a 3:1 linear:full hybrid — 48 Gated-DeltaNet layers + 16 gated GQA layers, hidden 5120, FFN 17,408, vocab 248,320 untied, 262,144 native context (memory; READ 5).

Two ways to read "fold Qwen into the Chimera skeleton":

| Reading | What it requires fold-only | What the record says about it |
|---|---|---|
| **(A) Translate** Qwen's mixers into Chimera's K3 mixers: GDN→KDA (per-dim decay), GQA+partial-RoPE→gated-MLA NoPE-576, SiLU→SiTU, pre-norm residual→Block-AttnRes | Four simultaneous structural steps on every layer, plus a NoPE-ification of 16 RoPE layers | *First composition step survivable, second fatal — held on five axes* (§C.27, the record's "most-replicated result"). Kind translation at real scale: conv→attention degraded (32–41% branch energy), attention→conv not viable (rho_far 0.52–0.69) (§D.60). RoPE geometry is dead structurally (HD16 0/15, HD48 1/15 vs registered 12; §D.51). Synthesis KILL LIST: post-hoc KDA conversion needs finetuning; every 2026 3:1 hybrid is a fresh pretrain (READ 5). **Dead fold-only.** |
| **(B) Embed exactly**: make `ChimeraConfig` a strict superset of Qwen3.8-27B's text trunk so the donor enters by a zero-solve, bit-exact embedding (zero fold steps spent), then spend the record's *one* survivable structural step on the components that actually pay for the 24 GB / 256k target | A handful of config-selectable variants in our own 12,113-line repo (list in §1) | Verbatim/exact mechanisms are the record's champions: verbatim coreset beats basis 40/42 (§D.48); vocab coreset bit-exact on kept text = the only 14/15 children (§B.18); exact-4x Chimera toy folds already carry receipts <1e-5 with 0 parent forwards (memory: b9e37374, ecb16477). |

**Recommendation: (B).** The Chimera skeleton keeps its identity (typed ledger, native media bridge/head, x0 flow, refinement mask, block kinds), and its *initial text configuration* is the exact image of Qwen3.8-27B. Chimera's K3-specific upgrades (per-dim KDA decay, MLA latent cache, SiTU, Block-AttnRes) become **stage-3 trained deltas**, switched on only after the folded trunk is recovered, and only where an export path exists. This is not a retreat from the K3 architecture; it is the record's composition law applied: you get one structural fold step, so do not spend it on a translation the record says dies.

Two things (B) eliminates outright, which matters for the retraining budget: it removes the need for the "KDA-from-softmax" fold class (Qwen's 48 GDN layers *are* the linear-attention stack; its 16 softmax layers stay softmax because the record's four-tax diagnosis and the field both put long-range retrieval there), and it removes expert-absorption (K3 is out as a weight donor, §2.2).

## 1. Skeleton changes required for an exact embed (Chimera-Q profile)

Every row is a config-selectable variant added to `src/chimera_omni/config.py` / `modeling/layers.py`; each must pass a bit-exact receipt against `transformers` Qwen3_5 on the same input before any fold runs.

| Qwen3.8-27B component (READ 5, memory) | Chimera today (READ 3) | Exact today? | Change needed |
|---|---|---|---|

Adopt Qwen's tokenizer + added tokens (GGUF-standard). Chimera has no tokenizer today (READ 3 OPEN) — this closes it. |
| 48 GDN layers: 16 key heads / 48 value heads × 128, conv k=4, per-head scalar decay `−exp(A_log)·softplus(a·x + dt_bias)`, SiLU(z)-gated output RMSNorm | `KimiDeltaAttention`: n heads with q,k = n·dk and v = n·dv (no key grouping), per-(head,dim) low-rank decay through sigmoid × gate_lower_bound(−5), `HeadwiseRMSNorm` × sigmoid(Linear) out-gate | No (three parameterization mismatches) | `kda_num_key_heads` (grouped keys), `kda_decay_kind = "gdn_scalar" \| "kda_diagonal"`, `kda_out_gate_kind = "silu_gated_norm" \| "sigmoid"`. Do **not** route Qwen's full layers into gated-MLA: an exact GQA-4×256-with-RoPE embed into a shared-rope-key MLA is representable in math (per-group zero-padded rope queries over a 4×64 concatenated rope key) but is not llama.cpp's rope schedule, so it breaks R3 standard export. |
| FFN SwiGLU 17,408, SiLU, no bias | Dense FFN `up: H→2I`, `down: I→H`, `activation_kind ∈ {silu, situ}` | Yes with `silu` | **`intermediate_sizes: tuple[int, ...]` per layer** — Cyril's mixed-ratio ruling (P22) needs per-layer widths; `ChimeraConfig` has one global `intermediate_size` today. SiTU stays OFF on folded layers: its tanh caps (β_g=4, β_u=25) are not identity on a trained SiLU FFN (activation is a sealed contract constant in the estate). |
| Pre-norm RMSNorm residual | `residual_mode ∈ {"none", "block_attnres"}` | Yes with `"none"` | Block-AttnRes cannot be switched on later as an identity: its zero-init pseudo-query gives a *uniform* softmax over depth sources, i.e., the mean of completed blocks + prefix, not the plain residual. The neural-forge kernel doc already flags AttnRes as a "single-global-chart fail-closed" hazard (memory f0ae9ab4). |
| 1-layer MTP head | `mtp_heads` (logits only, no loss) | Yes | Keep or excise (≈1/65 of a block; unsloth ships MTP GGUFs, so it is exportable). |

Runtime note: Chimera's KDA reference is a Python per-position loop and its attention materializes [B,n,T,T] (READ 3). Evidence capture on a 27B must therefore run through `transformers` Qwen3_5 (with `flash-linear-attention` installed in the lab venv for the GDN kernels — not inventoried, **ASSUMPTION** it installs against torch 2.11.0+cu128 / triton 3.6.0), on the RTX 8000 + a 3090 (bf16 27B = 54.6 GB does not fit one card; P40s cannot run bf16). Chimera's own modules are the *holder* of the weights for media training, not the capture engine.

Export mapping (R3): the text+vision trunk of a Chimera-Q child exports under llama.cpp `LLM_ARCH_QWEN35` (dense, GDN op present as F32 fused CUDA path, deepstack mmproj) — verified present on master (memory 2026-09-01; READ 5). Per-layer FFN widths: **ASSUMPTION** the generic hparams loader accepts a `feed_forward_length` array (it does for several archs); one tiny-GGUF probe settles it. The native media bridge/head, Fourier coordinates, σ-conditioning, typed ledger semantics and the x0 sampler have **no GGUF path on any runtime** (READ 3: GGUF "Not Imported"; mmproj is a clip.cpp graph, not Chimera's bridge). Deployable artifact on the 24 GB card = text+vision GGUF; media generation = Chimera torch runtime. That is a standing conflict between R3 and the encoder-free media path — decision item D3.

## 2. Per-donor fold plan

### 2.1 Qwen3.8-27B — language/knowledge/vision-understanding donor and the skeleton image

**Composition of the donor** (memory 2026-09-01; my arithmetic in parentheses): MLP 17.1B = 63% (64 × 3 × 5120 × 17,408 = 17.11B), attention ~6.9B (my count 7.2B: full layers ≈105M each × 16, GDN layers ≈116M each × 48), vocab 2.54B = 9% (248,320 × 5120 × 2), vision + MTP ~0.8B; total ≈ 27.3–27.6B. KV at 256k: 16 × 2 × 4 × 256 = 32,768 values/token → 16 GiB fp16, **8.5 GiB q8_0, 4.5 GiB q4_0**; GDN state fixed ≈148 MiB f32 (READ 5, memory).

**Budget arithmetic for the end goal** (usable ≈23.5 GiB; compute/logit buffers 1.5–2 GiB **ASSUMPTION** from READ 5; Q4_K_M ≈ 0.564 GiB per B params from unsloth's 15.4 GiB / 27.3B):

| Child | Params | Q4_K_M weights | KV @256k | Total w/ 2 GiB buffers | Fits 24 GiB? |
|---|---|---|---|---|---|
| Unfolded parent, q8 KV | 27.3B | 15.4 GiB | 8.5 | 25.9 | No (memory: "zero headroom" is optimistic) |
| Unfolded parent, q4_0 KV | 27.3B | 15.4 | 4.5 | 21.9 | Yes, ~1.6 GiB spare, zero room for media bands |
| Excise 4 of 16 full layers, q8 KV | 25.8B | 14.6 | 6.4 | 23.0 | Marginal; P40 needs slack |
| Excise 4 full + MLP coreset avg 0.6 (17,408 → ~10,445 mixed per layer), q8 KV | ≈19.3B | 10.9 | 6.4 | 19.3 | Yes, ~4 GiB for media bands (65,536 media rows ≈ 0.38 GiB at Q4), bridge/head, media tokens in context |

So the honest statement to Cyril: **the text-only end goal is already reachable by the unfolded donor + q4_0 KV (quantization-last, and q4_0 KV measured BLEU 1.000 on the hybrid Qwen3.5-9B, llama.cpp issue #21385)**. Folding buys three things: room for the media interface and media tokens, q8 KV (the safer long-context cache; DeepSeek-V4 shows K-quant garbage on indexer-MLA layers, issue #25382), and P40 throughput (346 GB/s; every GiB of weights re-read per token). Cyril's "25–30B" estimate does not fit with 256k q8 KV; ~19–22B does.

**Fold classes that apply, priced from the record** (all constants are LFM2 constants and *must be re-derived*; §B.32 "re-derive the constant; do not import"):

1. **MLP `intermediate_size` coreset, stream-selected (pivoted-QR channel selection), conditioned capture, per-layer mixed ratios.** The mechanism is config-standard on any gated FFN and "expected to transfer" (transfer table). This is 63% of the donor, so it is the only lever that reaches ~0.7x. Laws to carry: install 3-at-a-time, never all sites at once (ff640 all-14-sites 0/15 while 3-at-a-time survived; per-site write-cos cliff 0.93 alive / 0.86 dead, §D.46); the ladder is flat then cliffs (LFM2: 896→4, 1792→7, cliff 128 channels at 768→896, §D.47); price every candidate on the real folded base and re-price after acceptance (§C.32); conditioned capture is worth +3 cases at byte-identical storage (§C.34) but M-B-style re-solving of already-accepted components is dead (3 worse than control, 36× cost, §C.33). Verbatim channel selection beats low-rank on SwiGLU 40/42 (§D.48) — do not SVD the FFN.
2. **Interior-late excision of full-attention layers** — the KV lever. Each full layer removed = −6.25% of the 256k cache and ≈ −372M params (my count). Record: one interior-late block above parent (L13 13/15), pairs at distance 12 hold 7/15, three excisions collapse (13→7→3→0, §C.29, §D.53); first-of-kind and last-attention blocks are the expensive ones. On Qwen the 16 full layers sit at 3, 7, …, 63 (every 4th); by analogy L3 and L63 are the ones to leave alone, but censuses cannot rank (§A.6) — every candidate is built and reviewed. **Harness law is mandatory**: deleting a layer must re-derive Qwen's `layer_types` and assert zero attention mass above the diagonal (the LFM2 bug put 28.6–48.0% of attention mass on future tokens, §D.54). **Pre-registered risk**: excision priced on 4k-token evidence under-prices the loss at 256k if the full layers carry retrieval (the field's and the record's four-tax reading); cheap test = rank the census at 4k vs 32k evidence on the 4B (§6, T3).
3. **NoPE-dim contraction on the full layers (new cell).** LFM2 was fully RoPE'd, so its head_dim death (§D.51) was total; Qwen rotates only 64 of 256 dims. Contracting the 192 NoPE dims (256→192 or →160, rope 64 kept verbatim) is a cell the record never had. It is a low-rank fold, so the width law applies (retained reader energy is a ceiling, not a predictor, §D.49) — build and review, do not census. Exportable: `head_dim` and `rope.dimension_count = 64` are standard hparams.
4. **KV-head merge 4→2 on full layers — NOT the lever.** 16→12 joint-relation merge was 8/15 @0.979x; 16→8 (a 50% merge, the same ratio as 4→2) was 0/15 with any solve; merge costs 8–13× the drift/param of a SwiGLU lane; vocab × merge is FATAL (§D.52, §B.24). Use excision + KV quantization instead.
5. **Vocab coreset (deletion, zero-solve, bit-exact on kept text).** Here vocab is 9% (untied, V=248,320), far above the 2–6% the scaling doc projected for 7B–70B at V=32k–128k, so it is worth more than "~1%" on this donor. K = 128k removes ≈1.23B (4.5%). Costs: +15.8% sequence length on LFM2 (§B.18) — at 256k that is a real context tax; corpus floor and the 0.81 occurrence-coverage crossing are tokenizer/corpus properties and must be re-measured (§B.20, §B.15); the media bands need rows anyway. Composition: costs a body zero cases on 5/6 bodies, −3/−4 with excision, 1.17 interference with MLP (mildest pair), fatal with merge (§B.19, §B.24, §C.26). Decision item D4.
6. **GDN layers — keep verbatim.** ≈4.1B by my count (excluding their FFNs); state is fixed 148 MiB, so no memory lever; q/k folds survived only at one late site on LFM2 (§D.43); value-head merge 48→32 is the weak merge class. One probe cell (T5), no plan dependency.
7. **Terminal-gain arm (final-norm diagonal λ)** — +1–3 cases at shallow ratios, count-invariant, can lose below the +1 floor (§C.42). Apply last on the best composed child; cheap.

**Composition budget** (the record's hard law): at most **two** of {MLP coreset, excision, vocab} compose coherently on LFM2 (vocab+MLP: V19CL1792 7/15 @0.65x; vocab+excision: V20X13G03 11/15 @0.75x; MLP+excision at depth: 1/15; any three ≤1/15, §C.27, §3 built-working). Plan A therefore = **MLP coreset + 2–4 full-layer excisions** (the pair the 24 GB budget needs, and the pair LFM2 never held — so it is the first thing to measure on the 4B). Plan B if D4 rules vocab in = vocab + excision, no MLP (does not reach the budget table's last row).

**What fold-only gives, honestly**: on LFM2 the best coherent fold-only child at 0.5x was 4/15 (V12CL896G03 @0.451x) and 0.5x coherence was never achieved (PHASE1 §5). Plan A targets ≈0.70x of the donor, not 0.25x, precisely so that the folded trunk stays in the band the record calls "an initializer, not a product" (PHASE1 §6), with recovery distillation (§4) doing the rest. The unfolded Qwen3.8-27B is the teacher for that recovery — it is on the box and it is the only teacher whose residual space the child shares exactly.

**Fast-iteration ladder** (Cyril P47 "start with smaller versions"): Qwen3.5-0.8B/2B/4B/9B share the same `qwen3_5` architecture (4B: hidden 2560, 32 layers = 24 GDN + 8 full, 16/4 heads × 256, FFN 9,216, vocab 248,320 **tied**, 262,144 ctx; memory 2026-09-01). Same fold code end to end. Caveat: at 4B the tied vocab is ~16% of params, so 4B vocab results will not transfer to the 27B's 9% (interface-share law §B.17); MLP and excision results are the ones expected to transfer in shape.

### 2.2 Kimi K3 — architecture reference only (not a weight donor, not a local teacher)

Facts: official MoE, 2.8T total / 104B active, 93 layers = 69 KDA + 24 gated MLA, 896 experts × 3,072 + 2 shared, hidden 7168, vocab 163,840; on the box as 96 safetensors shards, 1,453.74 GiB, MXFP4-packed experts (compressed-tensors), non-expert tensors bf16 (READ 4).

Why it cannot be a fold source here:
- **Size**: K3's *non-expert* weights alone exceed the target. My count: KDA layers ≈ 4 × 7168 × 12,288 ≈ 352M + gates ≈ 380M × 69 ≈ 26B; MLA layers ≈ 140–150M × 24 ≈ 3.5B; untied embed+head 2 × 163,840 × 7168 = 2.35B; ≈32B before any FFN in layers 2–93. Memory's own ruling: "2.78T ⇒ ~100× over target: NOT a fold source (second-fold-step law), only architecture donor + later teacher."
- **Expert absorption has no closed-form path at this ratio.** The only published MoE→fully-dense conversion (arXiv 2605.28207) needs ~4B tokens of distillation; training-free methods (MergeMoE, ExFold, Sub-MoE, PuzzleMoE, HC-SMoE) do 50% expert cuts with calibration activations, and REAP/HARC warn merging loses routing control (READ 5). 896 experts → 1 dense FFN is an ~80× cut per layer; no evidence class within two orders of magnitude.
- **It cannot even run here.** Every absorption method needs K3 forward activations; llama.cpp K3 support merged 2026-08-15 but Q2_K ≈ 700 GB; the box has 184 GB VRAM + 251 GB RAM, no vLLM, and the shards sit on CIFS (READ 4/5). So K3 is also **not a usable teacher on this hardware**.
- **It is pre-quantized** (MXFP4 experts), which inverts Cyril's fold-before-quantize order for any expert weight.

What K3 contributes: the architecture, already absorbed in Chimera (KDA with lower-bounded decay −5, gated MLA, Block-AttnRes 12-layer blocks, SiTU; `KIMI_K3_ALIGNMENT.md`, K3-alignment suite 12 pass/1 skip), and its QAT-from-SFT recipe as the model for the Q4 step at the very end (int4 weight-only simulated on the 3090s; P40 has no bf16/fp8). If Cyril wants K3 weights in the child, the requirement is a different host (≥1.5 TB for bf16 dequant or ≥700 GB for Q2_K) — state it as such, not as a plan line here.

### 2.3 MiniMax H3 — AV architecture donor and (license-gated) teacher, not a weight donor

Facts: on the box only as ComfyUI repacks (fl2va pruned bf16 37.46 GiB = 20.11B elements; docs say ~33B), dense, no HF config; conditioner = frozen Qwen3-VL-32B (47.97 GiB bf16, 25.75B, 50 layers, dense full-attention); video VAE fp16 4.85 GiB, audio VAE fp32 0.56 GiB; flow-matching generator with no understanding head (READ 4, memory). Cyril ruled the US-license restriction inapplicable for internal, non-distributed use (2026-08-28); repo HEAD c1ca0b2 still fail-closed; relay task 8324ea96 pending Codex verification (READ 3, memory).

Why no closed-form weight fold exists:
- **No paired residual space.** H3 operates on VAE latents, bidirectionally; Chimera is encoder-free on raw patches, causal with a media-suffix refinement mask (READ 3). A Procrustes/ridge chart needs the same input in both models; there is none without also absorbing the VAEs (which the encoder-free rule forbids in the child).
- **No capacity to receive it.** 20B of AV flow weights into a ≤22B trunk that also holds the language function: sharing is falsified (55/56, §C.36), interface × body multiplies (§C.28), blends work only at shallow depth (§C.40). Nothing in the record supports two 20B functions co-resident fold-only.

What H3 contributes: (1) architecture — done (joint AV flow in one stream, x0 target, per-modality shifts video 12.0 / audio 3.0, refinement mask; v4 proof 13/13 gates at 3.19M params; memory 2026-08-28: "pure velocity target did not train at this scale; x0 did"); (2) **teacher** for AV generation distillation once the license gate is flipped (decision D10) — throughput is the constraint (LTX 2.3 took 331–361 s per 608×352 6-step clip on the RTX 8000; H3 is "slower but better" per Cyril; **ASSUMPTION** ≈1,000 teacher clips ≈ 4–6 GPU-days on a 3090); (3) **a teacher-side chart target**: a closed-form Orthogonal-Procrustes chart (R = UVᵀ from SVD(XᵀY), the winner in Atlas-Alignment, READ 5) from the child's residual stream to Qwen3-VL-32B's residual stream lets H3 be driven from the child's own states during distillation. That is Neural Forge's original bridge class, spent where the record says bridges work — on interfaces, not on body contraction (the proven 10–12/16 bridge frontier "NEVER contracted the body", memory W13T reframe). Per P34 ("[Cyril quote withheld]") a teacher-side chart costs zero at deploy. Within-family ridge/Procrustes charts retain 73–98% on 4 of 6 pairs and 42–44% on 2 (Cross-Model KV Transfer, READ 5) — measure, do not assume.

### 2.4 Image donors — teachers; image *input* is a decision

Qwen-Image 20.43B fp8 MMDiT + VAE + Qwen2.5-VL-7B text encoder (qualified t2i provider), SDXL base/refiner, ControlNets, IP-Adapter (READ 4). Same verdict as H3: latent-space bidirectional DiTs of 6–20B are teachers, not weight donors. The Qwen2.5-VL-7B encoder inside Qwen-Image is the second teacher-side chart target (child → Qwen2.5-VL-7B residual, within family).

Image **input**: Qwen3.8-27B's own SigLIP-class encoder + deepstack merger is the only Qwen-quality image-understanding path on the box, is standard-exportable (mmproj), and violates the encoder-free rule. Dropping it and folding its patch-embed + merger into the native bridge is a zero-solve init (patch conv → merger MLP → H) but functionally empty without the 27 ViT blocks between them — i.e., encoder-free image input at Qwen quality is a retraining line, not a fold (the estate's SmolVLM2 native fold reached 50.4% top-1 image-conditioned vs 25.4% text-only, memory 8dff2ea0 — a signal, not parity). Decision D2. Image **output** = native x0 flow head over raw patches (Chimera v4 class), trained from Qwen-Image/H3 teachers; the lossless bound is feature_dim 3072 (1·3·32·32), so 256×256 RGB at patch 16 = 768 features/token, 256 tokens/image; 1024×1024 = 4,096 tokens/image (context budget).

### 2.5 3D donors — gap on both sides

- **Speech (ASR/TTS)**: Qwen3-TTS/ASR and Whisper weights NOT FOUND (READ 4); only 256 LibriSpeech + 256 LJSpeech files local. No donor, no teacher, tiny corpus. Decision D8.

## 3. Fold order (skeleton first, then absorptions)
