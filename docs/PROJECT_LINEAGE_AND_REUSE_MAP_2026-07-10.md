# Project Lineage And Reuse Map

This note prevents a pivot from being interpreted as a clean-room restart. It
records which repository owns the folding product, which results remain active
evidence, and which explicitly selected interfaces from separate adjacent
projects may be consulted without merging their project boundaries.

## Canonical implementation

`neural-forge` is the only repository that currently implements model folding.
It already contains exact target construction and accounting, blank-target
bootstrap, cross-tokenizer byte alignment, canonical multi-parent traces,
coupled Q/K/V/O and gated-MLP operators, adaptive surgery graphs, codebook
runtimes, compensated folds, standalone checkpoint publication, and the full
parent-relative evaluation suites.

Development continues here. A new repository or replacement architecture is
not the default meaning of "pivot."

The two comparison anchors that may not be discarded are:

- the useful recovered 134,515,008-parameter child at approximately 29.9x;
- the zero-recovery Qwen codebook boundary with attention p35 and MLP p36.

The first is the product-quality/target-size frontier. The second is the
fold-only coherence frontier. A new candidate must be compared with both when
the comparison is applicable.

## Chimera Omni

`../chimera-omni` is a scale-free multimodal architecture project, not a
parent-to-child folding implementation. Its tiny semantic, artifact, routing,
and interference canaries are already established and must not be rerun as if
they were new compression evidence.

It remains its own Git repository. No Chimera history, code, artifact, or data
belongs in Neural Forge merely because an interface could be reused.

Reusable components:

- modality packet and masking ABI;
- route/provenance records and balanced sampling;
- causal-prefix invariance tests;
- artifact manifests and interference reporting;
- modality-specific test fixtures.

Components that do not satisfy the final product contract by themselves:

- the continuous-media bridge and linear output head;
- a permanently attached modality tower or projector;
- multitask music results that still miss the piano error threshold.

These interfaces may provide canonical parent traces and validation fixtures.
They do not replace Neural Forge's compiler or justify a permanent neural
sidecar in a published child.

## OmniCoder Qwen/LTX workspace

`C:/Users/cereal/Documents/Codex/2026-05-22/okay-here-is-the-deal-i/omnicoder_qwen_ltx_push_local`
is a provider-routed generation and packaging workspace, not a folding engine.

Reusable components:

- fail-closed target and artifact contracts;
- deployable-byte estimation and manifest patterns;
- provider/modality taxonomy;
- artifact-backed teacher records and contamination gates;
- optional disagreement/recovery records after fold-only promotion;
- richer optional shared media-head patterns where they can be compiled into
  the child rather than retained as runtime dependencies.

Its teacher/provider workflow is optional recovery infrastructure. It cannot
be used to relabel scratch training as folding, and it remains disabled while
the fold-only child is incoherent.

## Research and evidence corpus

`../ai-frontier-research-2026`, the dated validation documents, cached parent
evaluations, manual-review packets, and remote run artifacts are the project
evidence base. They are inputs to hypothesis selection; they are not a fourth
implementation that needs to be recreated.

The frontier corpus remains its own repository/data tree. Neural Forge records
only the specific research conclusions it actually uses.

The evidence has already closed the following unchanged paths as standalone
solutions:

- one-shot 25-30x mean, PCA, dual-coordinate, medoid, activation-subset, dense
  OT, and sparse-circuit transfers;
- extreme rank-one or shared-depth bases;
- uniform Qwen codebooks below the 35/35 survival boundary;
- local activation, hidden-cosine, PPL, or endpoint-fit promotion;
- recovery applied to a behaviorally collapsed fold;
- tiny architecture or artifact-exists canaries.

## Integration order

1. Continue from the executable codebook identity and p35 fold-only frontier.
2. Run bounded sensitivity collection and uneven mixed neuron/attention
   allocation with exact anchors, cached parent gates, rollback, evidence
   refresh, and a retained Pareto frontier.
3. Install the architecture-neutral sparse multi-anchor gated-MLP operator into
   the blank-target path, with hard candidate/work bounds.
4. Expose canonical simultaneous multi-parent compilation as a high-level,
   exact-budget entry point.
5. Progress through intermediate blank targets before the final 134M target.
6. Reuse Chimera modality packets and the NEO raw-RGB baseline only after the
   text compiler's fold-only gate is coherent.
7. Enable recovery and OmniCoder teacher records only after fold-only
   promotion, and measure training savings against an identical random child.

Every stage records zero-recovery and recovered results separately. No local
fit, smoke test, or structurally valid checkpoint can replace the behavior,
generation, choice, PPL/NLL, manual, save/reload, and exact-budget gates.
