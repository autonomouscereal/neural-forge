# Bounded student-prefix recovery candidate (2026-10-13)

The current structured D2 runner rejects `kind=onpolicy` and delayed/fractional sources. Its prepared train sources contain 12,253,101 real tokens and 9,634,142 assistant prediction positions. The historical 20M off-policy activation threshold cannot be reached by this exclusive corpus pass. The parent self-generated corpus is a different distribution: it does not show recovery on student-produced prefixes. The existing streamed engine implements cached on-policy bucket JSD but does not sample student continuations itself.

`train_onpolicy.py` prepares a **separate bounded snapshot round**. It does not alter the off-policy corpus, claim to produce teacher answers, or launch a model. The candidate uses the original full-depth streamed engine and structured accumulation normalization. The new round must be selected in a dated amendment, initialized from the exact accepted complete D2 full adapter bank, and run against its original uncomposed base. Its optimizer is fresh; same-round resume retains the exact sampler/optimizer/source pins. Importing adapters is initialization, not a different-data resume or summing banks.

The executable preparation stages are:

1. `prepare-prompts --training-paths ... --holdout-paths ... --exclusion-paths ... --split-inventory ... --output NEW_DIR` publishes only the prompt before the first assistant message, one prompt per connected source group. It screens the full recorded validation/test inventory, including quarantined rows, frozen evaluation text and global cross-route exclusions. A default 64 prompts per present text route and 256 generated tokens per prompt is a ceiling; missing coverage and short/EOS outputs are never padded or repeated.
   `add-tool-prompts --base TEXT_PROMPTS --ready READY --execution-receipts EXECUTIONS --seed-report REPORT --per-family 3 --output NEW_DIR` adds initial assistant tool-call prefixes from authentic executed train-only seed families. The actual October 13 set has 223 text plus 18 tool prefixes (three cases in each of six train-only families), a **61,696-token ceiling** and zero captured student tokens. Schemas, arguments and historical results are joined to exact execution/source/code/catalog pins; full normalized/frozen inputs and all held tool families are excluded. Only system/user input and authentic tool schemas enter the prompt. Historical calls/results remain provenance, not student targets or outcomes. Retry/parallel/multiturn family labels do not claim a student tool loop was executed. The declared scope is `initial_assistant_only_no_tool_dispatch`; trace receipts must preserve the schema digest and an empty `tool_outcomes` array. A later loop would need a separately reviewed runner that actually dispatches only the defined local seed tools and records every observed result.
2. A separately authenticated native decoder must capture genuine continuations from the accepted D2 state with the same native tokenizer/template/text vocabulary. There is no decoder fabricated by this preparation helper. Record every full answer, native prompt/generated IDs, checkpoint/template/tokenizer SHA, deterministic generation config, cap/EOS stop reason and the generation/code/runtime/acceptance receipts.

Wrong or repeated tokens remain student-prefix context; they are not hard training targets.
