# Bounded student-prefix recovery candidate (2026-10-13)

The current structured D2 runner rejects `kind=onpolicy` and delayed/fractional sources. Its prepared train sources contain 12,253,101 real tokens and 9,634,142 assistant prediction positions. The historical 20M off-policy activation threshold cannot be reached by this exclusive corpus pass. The parent self-generated corpus is a different distribution: it does not show recovery on student-produced prefixes. The existing streamed engine implements cached on-policy bucket JSD but does not sample student continuations itself.

`train_onpolicy.py` prepares a **separate bounded snapshot round**. It does not alter the off-policy corpus, claim to produce teacher answers, or launch a model. The candidate uses the original full-depth streamed engine and structured accumulation normalization. The new round must be selected in a dated amendment, initialized from the exact accepted complete D2 full adapter bank, and run against its original uncomposed base. Its optimizer is fresh; same-round resume retains the exact sampler/optimizer/source pins. Importing adapters is initialization, not a different-data resume or summing banks.

The executable preparation stages are:

1. `prepare-prompts --training-paths ... --holdout-paths ... --exclusion-paths ... --split-inventory ... --output NEW_DIR` publishes only the prompt before the first assistant message, one prompt per connected source group. It screens the full recorded validation/test inventory, including quarantined rows, frozen evaluation text and global cross-route exclusions. A default 64 prompts per present text route and 256 generated tokens per prompt is a ceiling; missing coverage and short/EOS outputs are never padded or repeated.
   `add-tool-prompts --base TEXT_PROMPTS --ready READY --execution-receipts EXECUTIONS --seed-report REPORT --per-family 3 --output NEW_DIR` adds initial assistant tool-call prefixes from authentic executed train-only seed families. The actual October 13 set has 223 text plus 18 tool prefixes (three cases in each of six train-only families), a **61,696-token ceiling** and zero captured student tokens. Schemas, arguments and historical results are joined to exact execution/source/code/catalog pins; full normalized/frozen inputs and all held tool families are excluded. Only system/user input and authentic tool schemas enter the prompt. Historical calls/results remain provenance, not student targets or outcomes. Retry/parallel/multiturn family labels do not claim a student tool loop was executed. The declared scope is `initial_assistant_only_no_tool_dispatch`; trace receipts must preserve the schema digest and an empty `tool_outcomes` array. A later loop would need a separately reviewed runner that actually dispatches only the defined local seed tools and records every observed result.
2. A separately authenticated native decoder must capture genuine continuations from the accepted D2 state with the same native tokenizer/template/text vocabulary. There is no decoder fabricated by this preparation helper. Record every full answer, native prompt/generated IDs, checkpoint/template/tokenizer SHA, deterministic generation config, cap/EOS stop reason and the generation/code/runtime/acceptance receipts.
3. `pack-traces --prompts ... --prompt-manifest ... --traces ... --generation-receipt ... --output NEW_DIR` fails before importing Torch without exact complete captured evidence. It writes native `input_ids`, `real_lengths` and an assistant mask covering the actual sampled continuation. Wrong or repeated tokens remain student-prefix context; they are not hard training targets.
4. Prepare a new `student_prefix_teacher.py prepare-plan` with exact prompt/policy/shape/distribution/paired/native-parity/source-plan/portable-proof/writer/engine file pins. The selected October 13 policy uses **singleton complete student sequences**: `--micro-batch 1 --max-batch-tokens 0 --batch-order corpus`, removing only actual padding. It preserves original Q64/fp32-head/bfloat16-trunk/native kernel/tokenizer and the referenced runtime image/interpreter/package profile. The original offline D2 paired-batch recipe is unchanged. The shape audit found exact identical cropped-single repeats but 17 top1 changes from batch dimension and 14 from right padding across 1,218 positions. Those results do not establish universal batch invariance or an intelligence/masking defect.
   Rescore actual captured student traces with the original writer, seal all files and before/after full parent digests, then `student_prefix_teacher.py seal-capture --teacher-plan ... --corpus-manifest ... --cache ... --runtime-receipt ACTUAL_ALLOCATED_RUN_PROOF --output NEW_RECEIPT`. The preparatory plan does not create a runtime receipt. Actual singleton source-bound forward/capacity and allocator/container/runtime proofs remain required. The original writer omits batching from its cache_config; the new guard authenticates every session and shard, exact microbatch/order/precision/runtime, one complete sequence per forward, no extra padding, and raw IDs/positions against the original student trace. Native packing includes identical `target_mask` and `assistant_mask`; the writer shifts the former to stored prediction positions. A cached historical parent answer cannot substitute for a student trace.
5. `bind-cache --corpus-manifest ... --cache ... --teacher-sha256 ... --round-receipt ... --teacher-plan ... --rescoring-receipt ... --output NEW_CONFIG` binds the new cache and accepted-bank lineage. `prepare-trainer --source EXACT_ORIGINAL_STREAMED_TRAINER --output NEW_CANDIDATE` emits an additive candidate. Run it with `--structured-recovery --student-prefix-round ROUND --init-adapters ACCEPTED_D2_BANK --data-config NEW_CONFIG`, the selected appended amendment and **`--w-q38 1 --w-ce 0 --w-eos 0 --w-ul 0 --onpolicy-divergence jsd --jsd-beta .5 --text-vocab-rows 248320`**. All objectives and initialization pins are checked before source/model construction. Each actual row is visited once; loss uses all assistant prediction positions in the entire accumulation window. Sealed singleton capture/source/runtime checks run again at every training run and exact resume, and their pins enter checkpoint identity.

`student_prefix_round.v1` records `student_acceptance_receipt` and `init_adapters` as exact file pins, the accepted `student_checkpoint_sha256`, original `base_source_identity_sha256`, `generation_receipt`, and the same `teacher_plan`/`rescoring_receipt` pins as the data config. The acceptance receipt must explicitly be stage D2, `accepted_complete_stage=true`, `bank_scope=D2.full_bank_replacement`, and contain those same checkpoint/base/adapter pins. The corpus generation receipt must bind that checkpoint. A runtime decoder receipt must prove actual generation; merely authoring a receipt does not establish it. The current preparation has no accepted D2 bank, generated student trace or parent rescoring cache and is not training-ready.

The actual teacher runtime wrapper must emit `student_prefix_teacher_runtime.v1`: `passed=true`, exact teacher-plan/cache-manifest SHA, unchanged `runtime_profile`, and `sessions` keyed by original session ID with its `cache_session_sha256` and an `allocation_forward_proof` file pin. Each external proof must carry actual allocation/container/GPU identity, the same session/runtime profile, and `native_singleton_forward_verified=true` only after the real source-bound forward check. The source helper checks recorded bytes; it cannot authenticate a manually invented allocation or generate missing outputs. Preparation publishes no such proof. A different runtime profile requires a new selected plan and fresh cache; prior cache metadata is preserved.

Cross-host read-only source mounts may supply `seal-capture --source-aliases JSON`: a SHA→absolute mounted-file map. Every file must have its original pinned bytes; only an unavailable source locator can be substituted. The runtime/capture receipt pins the exact alias file, and its SHA enters resume identity. The immutable teacher plan and all original source hashes stay unchanged. The prompt-manifest join uses exact bytes rather than requiring identical Windows/container path strings.

Evaluate a frozen matched baseline and after-round state using the existing full-answer semantic/tool evaluators. Keep semantic correctness and valid alternate answers separate from token retention: free-run positional match, LCP and exact consecutive-prefix horizons **5/8/16/32**, EOS/cap/repetition, and teacher-forced top-k position coverage. Save full answers, tool outcomes and model/corpus/template/decoding pins for both sides. Holdout text, tool trajectories and source groups never enter prompt sampling or optimizer rows. A correct answer fragment followed by a loop is a distinct result; EOS-only traces cannot inflate the eligible retention denominator.

This prepares one static snapshot round. It does not establish that multi-token retention, reasoning or modality quality has improved, nor that an online rollout objective ran historically. Source answers remain structurally admitted and ungraded unless a separate executable oracle established correctness. Lexical/source-group screening is bounded and does not exclude every semantic paraphrase. Do not launch until accepted-state, complete teacher cache, native decode/forward parity, exact runtime allocation and the separately selected round amendment exist.
