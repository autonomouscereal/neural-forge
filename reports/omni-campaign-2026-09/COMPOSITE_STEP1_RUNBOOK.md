## 3b. Known numerical traps (measured 2026-09-03; every implementer and reviewer must read)

- **Exact-zero RMSNorm gains exist in every Qwen parent.** Qwen3.5 norms apply `x * (1 + w)`; bf16 weights hit exactly
  −1.0, so the effective gain is exactly 0 on some coordinates. Census (`composite/receipts/norm_gain_census.json`):
  Qwen3.8-27B-Uncensored: `layers.7.post_attention_layernorm[3994]`, `layers.43.self_attn.k_norm[32]`,
  `layers.59.self_attn.q_norm[1]`; Qwen3.5-4B: `layers.27.self_attn.q_norm[1]`; Qwen3.5-0.8B:
  `layers.23.self_attn.q_norm[0]`. Any code that divides a solved row by a norm gain (C7 did, and died at 4B layer
  27 with Inf → NaN stream → NaN Gram → Cholesky "leading minor of order 1") must install the parent's raw row on a
  zero-gain coordinate instead (`qf_attn.unfold_gain`, recorded as `zero_gain_coordinates`). The 27B's zero at
  `post_attention_layernorm` L7 feeds the MLP input: C2 / C14 / C10 captures on that layer carry a structurally dead
  input channel — never divide by it, never treat it as a fit failure, and record it.
- **Gram defects must be named, never silently caught.** `qf_solve.prior_anchored_gram` now raises
  `GramNotPositiveDefinite` with the offending channels and the ridge; the eigen fallback (`EIGEN_FLOOR_REL = 1e-12`)
  is recorded per rung as `solver_fallback`; a non-finite Gram is a refusal. Non-finite captured rows are dropped
  and counted by `_resolve_writer` (`stream_repair`, ceiling 2%). Reuse these; do not reimplement a bare Cholesky.
- **bf16 on the Broadwell CPUs is 400x slower than fp32** (no AVX-512): every CPU column is fp32.
- **The SSH client caps each command at 300 s**: long steps run detached and are polled.
