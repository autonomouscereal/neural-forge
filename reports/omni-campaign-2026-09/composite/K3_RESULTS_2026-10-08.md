## What "record" mode means (confirmed from the tool, v1.2.4, codex/validated)

- `--acceptance {gate,record}`, default `gate` (lines 3033-3036): "'record' computes and records the verdict without enforcing it (synthetic mechanics tests) -- the receipt says which".
- `evaluate_acceptance(..., mode)` sets `enforced = (mode == "gate")` (line 1282). In `accept_layer` (lines 2328-2357) a refusal **removes `ffn.safetensors`, drops the layer from `self.installed` and raises `Refusal` only when `acceptance["enforced"]`**; otherwise the code falls through to "accepted (or record-only): the done marker carries the metrics INCLUDING the verdict" and writes `done.json`. The folded stream had already been advanced with the installed child before `accept_layer` is called (`run_layer` line 2245 computes `stream_divergence(new_teacher, new_folded)`, then line 2248 `accept_layer`).
- Therefore in this run **every fitted layer L1-35 is installed and every refused layer's child keeps writing into the folded stream** that feeds every later fit. Evidence: `fold/dense/L06..L35/ffn.safetensors` + `done.json` all present; `closed.installed_ffn_sha256` lists all 24 of L1-24 including the refused L6, 9, 10, 11, 14, 16-23; `start.files.folded.stamp.installed_layers` = 24 at L25. The fitter log prints `acceptance REFUSED (record only, not enforced)` for each.
- `read_done_marker` (lines 1890-1898) only demands `verdict == "accepted"` when resuming in **gate** mode. A gate-mode resume from this tree would reject every refused layer's marker and refit from the first refused layer (L6), with the prefix lineage re-derived.
- So the prefix 0-35 that exists on disk is a **record-mode prefix**: it contains 21 layers that the measured rule says should not have been installed. Snapshots `before_L25_folded` / `before_L36_folded` carry that lineage (`installed_ffn_sha256` stamp lists L1-24 / L1-35).
