### 0.2 Forward semantics that change the algebra [verified on server file unless noted]
* `Qwen3_5RMSNorm.forward = normed(x) * (1.0 + weight)`; init zeros. EFFECTIVE GAIN g = 1 + w. Applies to input_layernorm, post_attention_layernorm, final norm, q_norm, k_norm. (LFM2 used g = w.)
* `Qwen3_5RMSNormGated` (GDN `.norm`): `weight * rmsnorm(o) * silu(z)` — weight used directly (no 1+); per head_v_dim (128), applied on rows reshaped `(-1, head_v_dim)` (shared across value heads) [verified in github main; server 5.12.1 line 187 same class name, body assumed identical; the fla `FusedRMSNormGated` path is taken when `fla` imports — fla 0.5.2 IS NOW INSTALLED in the venv, and that constructor calls `torch.cuda.current_device()` at __init__ -> a CPU-only process may fail to instantiate the model; pin `CUDA_VISIBLE_DEVICES` or monkeypatch `FusedRMSNormGated=None` for CPU-only loads].
* GDN forward: `mixed_qkv = in_proj_qkv(x)`; conv1d (depthwise, k=4, no bias) + SiLU (torch fallback `F.silu(conv1d(x)[:, :, :L])` because `causal_conv1d` is NOT installed [verified]); split [Kd, Kd, Vd]; `beta = sigmoid(in_proj_b(x))` per value head; `g = -exp(A_log) * softplus(in_proj_a(x) + dt_bias)` per value head (fp32); q,k `repeat_interleave(nv//nk, dim=heads)`; q,k L2-normalised IN-KERNEL (`use_qk_l2norm_in_kernel=True`), query scaled by head_k_dim**-0.5; state per value head [128 k x 128 v]; output `norm(o, z)` then `out_proj`. Kernel: fla `chunk_gated_delta_rule` (Triton) when fla imports, else torch chunk impl.
* Attention forward: `q, gate = chunk(q_proj(x).view(..., nh, 512), 2, -1)`; `q = q_norm(q)`, `k = k_norm(k)` (per-head RMS over 256 with (1+w)); RoPE on the FIRST 64 dims only (`partial_rotary_factor 0.25`, `rotate_half` pairs dim p with p+32, p<32); dims 64..255 are NoPE (pass-through); softmax(q k^T / 16 + mask) (eager returns attn_weights); `attn_output * sigmoid(gate)` elementwise per head dim; `o_proj`.
* RoPE: `inv_freq_j = 1e7 ** (-2j/64)`, j<32; cos/sin shape [.., 64] (`cat(freqs,freqs)`); MRoPE interleaved sections [11,11,10] — for text-only inputs all three position rows are equal so it reduces to plain RoPE [verified code]; `rotary_emb` lives on `language_model`, computed once per forward from `position_ids` (expanded to 4 rows; row 0 = text).
* Mask dispatch in `Qwen3_5TextModel.forward` (5.12.1 line ~1201): `layer_mask = linear_attn_mask if self.config.layer_types[i] == "linear_attention" else causal_mask` — POSITIONAL BY CONFIG LIST, exactly LFM2's wave-18 trap. With `attention_mask=None` the linear mask is None; an attention block shifted into a linear slot receives None and ATTENDS TO THE FUTURE. A GDN block shifted into a full slot receives the 4D causal mask, which `apply_mask_to_padding_states` silently ignores at batch 1 (it only multiplies when `mask.shape[0] > 1 and mask.shape[1] > 1`) — so the trap is asymmetric and only the attention direction is observable in outputs. The loop is `self.layers[: self.config.num_hidden_layers]` so `num_hidden_layers` must be re-derived too. Caches index `layer_idx` (both GDN conv/recurrent states and KV) -> re-index after excision.
* Config (`Qwen3_5TextConfig`, `text_config` sub-config of `Qwen3_5Config`) [verified]: `head_dim` IS an explicit field (default 256) — no LFM2 `hidden_size // heads` fallback trap; `layer_types` derived from `full_attention_interval` (4) when absent; GDN geometry is its own fields `linear_num_key_heads`, `linear_num_value_heads`, `linear_key_head_dim`, `linear_value_head_dim`, `linear_conv_kernel_dim` — independent of `hidden_size`; `partial_rotary_factor` lives in `rope_parameters` (and is duplicated top-level in the 27B config); `tie_word_embeddings` True at 0.8B/4B, False at 27B; `mtp_num_hidden_layers: 1`, `mtp_use_dedicated_embeddings: false`; vision sub-config `out_hidden_size` == text hidden.

### 3.2 `qf_gdn.value_head_axis` (C5) — GDN value-head fold, two arms
Per value head j (nv heads, nk key heads, group g = nv/nk: 3 at 27B, 2 at 4B, 1 at 0.8B), the head's tensors are: `in_proj_qkv` rows `2Kd + j*128 + arange(128)` (value part), `conv1d.weight` the same channel rows, `in_proj_z` rows `j*128 + arange(128)`, `in_proj_b` row j, `in_proj_a` row j, `dt_bias[j]`, `A_log[j]`, `out_proj` columns `j*128 + arange(128)`; the state is [128 x 128]; `norm.weight` [128] is shared across heads. q/k rows for key head m: `in_proj_qkv` rows `m*128+arange(128)` (q) and `Kd + m*128 + arange(128)` (k), conv rows likewise; head j reads key head `j // g` (`repeat_interleave`).
Config legality: `linear_num_value_heads % linear_num_key_heads == 0` [verified forward]; both are config fields, so head-count children are stock.
* **Arm A — head COUNT (`--gdn-value-heads nv'`, `--gdn-key-heads nk'`)**: rungs at 27B 48/16 -> 24/8 (2x, diagnostic) -> 12/4 (4x) -> 6/2 (8x); 4B 32/16 -> 16/8 -> 8/4. GAUGE: the delta rule has NO RoPE and q,k are L2-normalised per head in-kernel, so for a key head any ORTHOGONAL Q on the 128 key dims is an exact gauge (q -> Qq, k -> Qk, S -> QS leaves q^T S invariant) — full Procrustes alignment applies (stronger than LFM2's sign gauge); value dims have no norm before the state either, so the value gauge is any orthogonal P with `out_proj` columns rotated by P^T and `z` rows by P (the gated RMSNorm is over all 128 dims of a head: invariant under an orthogonal P on the head EXCEPT the elementwise `weight` and the elementwise `silu(z)` gate — so the exact value gauge is per-dim sign again; use Procrustes as the census and sign as the install gauge, record `rotation_gauge_gain` as head_count_axis does). Pairing census on post-conv, L2-normed q/k rows and on (beta_j, g_j) time series (two heads in one key group share q,k exactly; merging them = merging their decay/beta/value): order pairs by `0.5*(k_cos_in_gauge + v_cos_in_gauge) - |g_a - g_b|_rms`. Merge: key rows = joint relation solve is not needed (no per-plane structure): merged k = evidence-energy-weighted average in gauge, recovered by `direction_anchored_solve` against the L2-normed target (gain = ones, eps = 1e-6 as in `l2norm`); q likewise; conv taps averaged in gauge (4 taps per channel); value/z: evidence-whitened LRA of the two heads' joint 256-dim value space to 128 (the `head_dim_axis` v-contraction, P from `stack @ Rt` where `stack` = `out_proj` columns of both heads), applied to BOTH `in_proj_qkv` value rows and `in_proj_z` rows (the gate must live in the same frame; inexact, recorded as `z_frame_mismatch`); decay/beta: `a` row, `dt_bias`, `A_log` of the merged head = the ANCHOR head's (higher energy) as the prior, then `in_proj_b`/`in_proj_a` rows re-fit in closed form so that `sigmoid(b'x)` and `softplus(a'x + dt')` match the energy-weighted parents on the evidence (logit / inverse-softplus targets, prior-anchored ridge under THE LAW; `A_log` kept at the anchor's — it is a per-head scalar and the ridge on `a` absorbs the scale); `out_proj` prior = `[Wo_a Wo_b] P^T`, then re-solved against the LOCAL target with the installed module (`law_abiding_solve` on the captured `out_proj` input) — the GDN's `out_proj` input is a module input, so no probability recompute is needed (unlike attention). Control arm `--gdn-solve drop`: delete the lowest-energy heads outright, re-solve `out_proj` only.
* **Arm B — head DIM (`--gdn-value-head-dim d_v'`, `--gdn-key-head-dim d_k'`)**: config fields `linear_value_head_dim` / `linear_key_head_dim` exist [verified], so a contracted head is stock. 128 -> 32 = 4x on v/z/out_proj and on the state's v side; key 128 -> 32 = 4x on q/k/conv and the state's k side. ### 3.4 `qf_solve.gated_value_pair_solve` — the exact operator for v | o_proj with gates
With probabilities `A_h` fixed and gates `s_h(i) = sigmoid(X_i Wg_h^T)` [N x 256] fixed, `out(i) = Σ_h Wo_h diag(s_h(i)) Wv_{g(h)} z_h(i)`, `z_h = A_h X`. Linear in `Wv_g` and in `Wo`, but the per-position diagonal breaks the Kronecker (Stein) form. Solve `Wo` with `Wv` fixed = ordinary ridge on the captured (gated) `o_proj` input — exact, `law_abiding_solve[_split]` unchanged. Solve `Wv_g` with `Wo` fixed: apply the operator `T(S) = Σ_h Σ_i (Wo_h^T [Wo_h (s_h(i) o (S z_h(i)))]) z_h(i)^T` (cost N * heads * 256 * H per application; N ~ 6k rows, H 5120 -> fine on a GPU in fp32/fp64), CG on `T + lam I` preconditioned by `stein_two_sided_eigh` with the MEAN gate folded into the left factor (`L_h = Wo_h^T diag(mean s_h)^2 Wo_h`), lambda by `law_abiding_stein[_split]`'s ladder (same LAW, same internal check split). Gate on the recompute: predicted `o_proj` input `cat_h(s_h o (A_h X Wv^T))` vs the installed module's own (`ATTENTION_RECOMPUTE_TOLERANCE 5e-2`); `attention_gate_probe` compares `A_h` against `attn_weights` from eager as before.
