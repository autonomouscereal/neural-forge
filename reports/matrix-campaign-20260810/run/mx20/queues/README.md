# `run/mx20/queues/` — the wave-20 operational drivers, as they ran

These are the scripts that drove the wave from `/home/cereal/nf-mx20` on the
server. They are committed for the same reason the dossiers are: the wave's
numbers are only reproducible if the order the children were built and read in
is legible. `env.sh` names the one deployment every one of them sourced.

| queue | what it did |
|---|---|
| `parity.sh` | the conditioned capture against the sealed collector, before anything was built |
| `selectorq.sh` | the free retention measurement — pooled, retrieval and procedural rows, against every sealed wave-19 basis, a beta grid and the generalised subspace. It runs FIRST and it can falsify the wave's hypothesis without a build |
| `basisq.sh` | one sealed basis artifact per (mode, width, beta) the wave builds against |
| `widthq.sh` | the rungs, one build per rung against its own sealed basis |
| `reviewq.sh` | seal + frozen review, one child per invocation, **refusing a tag that is already sealed** — wave 19's double-seal, fixed at the driver instead of at the merge |
| `../sealq.sh` | the ADDENDUM 6 verdicts, each a case-by-case reading of a frozen dossier |
| `../run-bench.sh` | the ADDENDUM 8 column, parent first |
| `../probeq.sh` | the two never-built slate classes, CBT and F-LANDMARK, at their named sites |
